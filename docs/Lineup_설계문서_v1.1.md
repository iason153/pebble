## 1. 문서 목적

이 문서는 Pebble 프로젝트의 첫 번째 툴 Lineup의 **v1 개발 착수 기준 문서**다. 대표가 v1.0 설계를 직접 검증하는 과정에서 두 가지 핵심 전제(iOS 공유 연동 가능 여부, 유튜브 알고리즘 개입 없는 연속 재생 가능 여부)에 기술적 한계가 있음을 확인했고, 이를 반영해 실행 가능한 범위로 재설계했다. v2(임베드 하이브리드 플레이어, 알고리즘 무개입 모드)는 v1 배포 후 운영 상황을 보고 착수 여부를 판단한다.

## 3. 핵심 컨셉 (v1.0과 동일 유지)

Lineup은 재생 플랫폼이 아니라 **큐 관리 도구**다. 유튜브 영상을 자체 재생하지 않고, 순서를 관리해 유튜브에서 순차 재생하도록 넘겨주는 역할에 집중한다.

```
평소 → 유튜브에서 마음에 드는 영상 발견 → 링크 복사 또는 공유로 Lineup 큐에 추가
전날 밤 → Lineup에서 큐 순서 드래그 정렬, 통근시간에 맞춰 분량 확인
출근 아침 → "재생 시작" → 유튜브에서 큐가 순서대로 이어짐
```

### 3-1. Lineup이 풀지 못하는 것 (검증을 통해 확인한 한계)

설계 검증 과정에서 아래 두 가지는 **Lineup의 설계 문제가 아니라 유튜브 정책상 외부 툴이 넘을 수 없는 벽**임을 확인했다. 이를 문서에 명시해 이후 "왜 안 되는가"에 대한 재검토가 반복되지 않도록 한다.

- **영상 시청 도중 끊김 없이 여러 개를 연달아 큐에 담는 것**: 유튜브가 2026년 1월부터 무료 사용자의 백그라운드 재생(앱 전환 시 재생 유지)을 서버 단에서 전면 차단했다. 앱을 전환하는 순간 시청 중이던 영상이 멈춘다. 이는 유튜브 자체의 무료/프리미엄 정책이며 외부 PWA가 우회할 방법이 없다.
- **유튜브 자체 추천 알고리즘을 완전히 배제한 연속 재생**: 큐가 끝난 뒤 유튜브의 자동재생이 개입하는 것을 막으려면 임베드 플레이어로 직접 재생 상태를 제어해야 하는데, 이는 v1 범위를 벗어난다(§8 참고).

### 3-2. Lineup의 실질 차별점

- 유튜브 자체 "대기열(Queue)" 기능은 **프리미엄 전용**이며, 미니플레이어를 닫으면 초기화된다(세션 간 미유지).
- 유튜브 "나중에 볼 동영상(Watch Later)"은 순서 변경이 가능하지만 **구글 로그인이 필수**이고, 모바일 UX가 최적화되어 있지 않다(데스크탑 확장 프로그램들이 다수 존재하는 이유).
- Lineup은 **로그인 없이, 모바일에서, 통근시간에 맞춰 분량까지 계산해주는** 지점에서 차별화한다.

## 4. 핵심 설계 결정 및 근거

### 4-1. 재생 방식 — `watch_videos` 링크를 이용한 일괄 전달 ("튕김 전용")

**결정**: Lineup 내부에서 영상을 재생하지 않는다. "재생 시작"을 누르면 큐에 담긴 영상 ID들을 모아 `youtube.com/watch_videos?video_ids=ID1,ID2,ID3...` 형태의 링크 하나를 생성해 유튜브 앱 또는 탭으로 연다.

**결정 근거**:
- 이 엔드포인트는 로그인 없이 여러 영상 ID로 유튜브 서버에 임시 재생목록을 생성하며, 이후 다음/이전/자동재생 UI를 유튜브가 전부 처리한다. 2026년 시점에도 정상 작동이 확인된다.
- 개별 영상 재생 종료 후 "Lineup 복귀 → 다음 영상 안내"를 직접 구현할 필요가 없어 v1.0 대비 재생 관련 코드가 크게 단순해진다.
- 임베드 차단 영상(연령제한·업로더 차단·저작권 제한)도 유튜브 자체 페이지에서 재생되므로 문제가 되지 않는다.

**리스크 (명시 필요)**: `watch_videos`는 유튜브가 공식 문서화하지 않은 엔드포인트다. 유튜브가 언제든 변경하거나 차단할 수 있다. **폴백 계획**: 엔드포인트가 작동하지 않을 경우, 큐의 첫 영상 링크만 여는 방식(개별 영상 순차 안내, v1.0 원안 수준)으로 즉시 전환할 수 있도록 재생 로직을 모듈화해서 구현한다.

**순서 보장 및 예외 처리**: `video_ids` 파라미터에 나열한 순서가 그대로 재생 순서가 된다. 재생 중 특정 영상이 삭제·비공개로 전환된 경우, 유튜브가 "재생할 수 없는 동영상"으로 표시하고 다음 항목으로 자동 진행한다(일반 유튜브 재생목록과 동일한 표준 동작이며 Lineup이 별도로 처리할 부분은 아니다).

**큐 종료 후 동작**: 큐 재생이 끝나면 유튜브 자체 화면(추천 영상 등)으로 자연스럽게 이어진다. v1에서는 이를 막지 않으며, 별도 안내도 넣지 않는다 — 큐를 다 본 이후엔 유튜브 추천을 봐도 무방하다는 것이 v1의 전제다.

### 4-2. 큐 추가 방법 — 3경로, 우선순위 재조정

**결정**: URL 붙여넣기를 1군, 클립보드 자동 감지를 2군으로 하고, PWA 공유 연동은 **안드로이드 전용 보조 경로**로 격하한다.

| 방법 | 역할 | 지원 범위 | 사용자 노출 방식 |
|---|---|---|---|
| URL 직접 입력 | 1군 (모든 환경 공통) | 전체 | 입력창 항상 노출 |
| 클립보드 자동 감지 | 2군 | 전체 (iOS 포함) | 앱 복귀 시 클립보드의 유튜브 링크 자동 감지 → 추가 제안 |
| PWA 공유 연동 (Web Share Target) | 3군, 안드로이드 전용 | Android Chrome만 | 안드로이드에서만 온보딩 시 안내 |

**변경 근거**: iOS Safari는 Web Share Target API(공유 "받기")를 명시적으로 미지원한다(WebKit 이슈 트래커 기준 "neutral" 입장으로 장기 정체). v1.0처럼 "공유 버튼 누르면 됩니다"를 메인 동작으로 안내하면 iOS 사용자에게는 그 진입점 자체가 존재하지 않는다. 온보딩 문구도 OS 불문 동작하는 표현으로 재작성한다.

**실사용 흐름 (가장 흔한 단일 영상 추가)**:
```
유튜브 앱에서 영상 발견 → 공유 시트 → "링크 복사" 탭
(앱 전환 없음, 보던 영상 계속 재생됨)
→ 이후 Lineup을 열면 "방금 복사한 링크, 큐에 추가할까요?" 자동 제안 → 탭 1회로 완료
```

**여러 개를 연달아 담을 때**: 클립보드는 1개만 기억하므로, 매번 Lineup에 짧게 들렀다 돌아가야 한다(§3-1 한계 참고). Lineup을 열면 즉시 자동 추가되고, 화면에 "돌아가기" 버튼을 크게 노출해 복귀 마찰을 최소화한다.

### 4-3. 통근시간 맞춤 큐 (신규 기능)

**결정**: 큐 화면에 "이동시간" 슬라이더를 추가한다. 사용자가 목표 시간(예: 20분)을 입력하면, 큐에 담긴 영상들의 누적 재생시간을 계산해 그 시간 안에 들어가는 영상까지만 하이라이트하고, 넘어가는 영상은 흐리게 표시한다.

**결정 근거**: 핵심 시나리오("출근 아침 → 재생 시작")에 "얼마나 볼 수 있는가"라는 실질 정보를 더한다. 유튜브 자체엔 대기열의 누적 시간을 목표 시간에 맞춰 잘라주는 기능이 없어 차별점으로 유효하다.

**기술적 전제**: YouTube oEmbed는 영상 길이(duration) 필드를 제공하지 않는다. 이 기능을 위해 **YouTube Data API v3의 `videos.list?part=contentDetails`**를 별도로 호출해야 하며, API 키 발급과 일일 쿼터 관리가 신규로 필요하다. (§6 기술 스택에 반영)

### 4-4. 모바일 우선 설계 원칙 (v1.0과 동일 유지)

- 터치 조작 기준 설계, 버튼 최소 크기 48px
- 큐 순서 변경: 롱프레스 드래그 방식
- 한 화면에 핵심 기능 하나
- localStorage 기반 저장 — 앱 재진입/재부팅 후에도 큐 상태 그대로 유지

## 5. 기술 스택

| 항목 | 내용 | 비고 |
|---|---|---|
| 구현 방식 | HTML / CSS / JavaScript — 서버·DB 없음 | v1.0과 동일 |
| PWA | manifest.json + Service Worker | 안드로이드 공유 연동을 위해 유지 |
| 공유 연동 | Web Share Target API | **안드로이드 전용 보조 경로로 축소** |
| 클립보드 감지 | Clipboard API | 1군 경로로 격상 |
| 데이터 저장 | localStorage | 동일 |
| 영상 메타데이터(제목·썸네일) | YouTube oEmbed API | 인증 불필요, 동일 |
| **영상 길이(신규)** | **YouTube Data API v3 `videos.list?part=contentDetails`** | **신규 의존성 — API 키 발급, 쿼터 관리 필요** |
| 재생 | `youtube.com/watch_videos?video_ids=...` 링크 오픈 | 비공식 엔드포인트, 폴백 로직 필수(§4-1) |
| 인프라 | 기존 EC2 활용 | 동일 |

## 6. 기능 정의

|---|---|

| `watch_videos` 엔드포인트가 비공식이라 유튜브가 언제든 변경/차단 가능 | 재생 기능 전체 마비 | 개별 영상 순차 안내 방식으로 즉시 폴백 가능하도록 재생 로직 모듈화 |
| iOS Web Share Target 미지원 | 공유 연동이 안드로이드 전용으로 축소됨 | URL 붙여넣기·클립보드 감지를 1·2군으로 이미 반영, iOS는 이 경로로 커버 |
| 무료 사용자 백그라운드 재생 차단(2026.1~) | "끊김없이 여러 개 담기"는 애초에 불가능 | 온보딩·문서상 목표를 "끊김없음"이 아닌 "복귀 마찰 최소화"로 명확히 재정의 완료 |
| YouTube Data API 신규 의존(쿼터) | 통근시간 기능이 쿼터 초과 시 동작 불가 | contentDetails 단일 필드 조회로 쿼터 소모 최소화, 실패 시 통근시간 기능만 비활성화하고 나머지는 정상 동작 |

## 8. v2 로드맵 예고 (착수 시점 미정 — v1 운영 상황 보고 판단)

- **임베드 하이브리드 플레이어**: 임베드 가능 영상은 Lineup 자체 화면에서 재생(YouTube IFrame Player API), 임베드 불가 영상만 유튜브로 튕김. 임베드 가능 여부 판단을 위해 YouTube Data API `status.embeddable` 필드 추가 조회 필요.
- **알고리즘 무개입 재생 모드**: 위 임베드 플레이어를 기반으로, 영상 종료 이벤트를 직접 감지해 유튜브 자동재생이 개입할 틈 없이 큐의 다음 영상으로 전환. 유튜브 관련 UI(추천 영상 등)도 `rel=0`으로 차단.
- 착수 시 난이도가 ★★★★ 수준으로 상승할 것으로 예상되며, v1 배포 후 실사용 데이터(임베드 차단 영상 비율, 사용자 체감 불편 지점)를 보고 우선순위를 재판단한다.

| 5단계 | SEO/AEO, 애드센스 슬롯 확보, QA(iOS/안드로이드 교차 테스트 포함), 배포 | 19~21일 |
