## 1. 한 줄 정의

고지서를 찍기만 하면 **무엇을 · 얼마 · 언제까지**를 읽어 마감 전에 알려 주는 도구. 장부가 아니라 **"독촉장을 안 받게 하는 마감 알리미"**. 고지서가 없는 것(구독·자동이체·대출 상환)도 직접 등록하면 똑같이 알려 준다.

## 2. 사전 시험 결과 (2026-10-14)

| 방식 | 결과 |
|---|---|
| 1차: Tesseract.js 한글, 원본 1회 읽기 + 규칙 | 건보 5장 중 5장 ✅ (글자 신뢰도 58~72) |
| 2차: 8장(건보 5·가스 1·재산세 2), 원본 1회 | 6/8 (압류예고 금액, 재산세 기한 실패) |
| **3차: 원본 + 손질본 두 번 읽고 투표 + 규칙 보강** | **8/8 ✅** (신뢰도 평균 77, 최고 84) |

- 손질본만 쓰면 오히려 가스 고지서가 틀렸다 → **둘을 합치는 것이 핵심**.
- 결론: 무료·폰 안 방식으로 가능. 단, 글자 전체가 깨끗한 건 아니며 **금액·날짜·기관 3가지**를 규칙으로 골라내는 것이 본질. 사용자 확인 화면이 필수.
- 시험 사진·읽은 글자는 모두 삭제함. 전기·관리비·카톡 캡처는 미검증.

## 3. 절대 조건 (지킨 것)

- 비용: 글자 읽기는 Tesseract.js(폰 안), 추출은 규칙. 유료 AI 없음. 서버는 Vercel Pro(이미 구독) + Upstash Redis 무료 등급.
- 개인정보: **사진은 폰 밖으로 안 나감**(v1.1부터 폰 안 IndexedDB에만 보관, 냈어요 후 30일 뒤 자동 삭제). 데이터는 localStorage. 로그인 없음.
  - 서버에 올라가는 것: 익명 기기키, 푸시 구독 주소, 알림 시각, 항목의 **이름·마감일만**. 금액·주소·납부자번호·사진은 절대 안 올림.
  - GA4(G-4Q8F4E2J61, tool=billbox): 종류·개수·성공 여부만. 금액·이름 금지.
- 디자인: 모바일 기본, min-width로 확장, 버튼 48px 이상, 320px·큰 글씨 가로 넘침 0, word-break keep-all, 인앱 브라우저 안내.
- 폰을 바꾸면 사라진다는 안내: 첫 화면 + 설정(백업 파일 받기/불러오기 제공).

## 4. 화면 (3 + 보조)

1. **홈** — 요약 스티커(이번 주 낼 건수·합계, 지난 게 있으면 빨간색) → 🚨 마감 지남 / 📌 이번 주 / 📅 다음에 / 낸 것(접힘). 카드마다 D-day·[냈어요]. 아래 고정: [📷 고지서 찍기] [✏️ 직접 입력].
2. **찍기 → 확인** — 촬영 팁 3컷("바닥에 펴고 · 그림자 없이 · 금액·기한이 보이게", 대충 찍어도 최선) → 카메라/앨범(카톡 캡처) → 진행 표시(2단계) → "읽은 내용, 맞나요?" 자신 없는 칸엔 빨간 **확인!**, 후보 칩("혹시 이건가요?"), 같은 종류가 이미 있으면 "그걸 이 고지서로 바꾸기/따로 추가".
3. **상세** — 금액 크게, 기한·D-day, 반복, [냈어요] [📅 캘린더 알림(.ics)] [고치기] [지우기], 낸 기록.
- 보조: 설정(푸시 켜기/끄기·시험 알림·알림 시각·언제 알릴지·백업), 설치 안내, 인앱 배너, 토스트(되돌리기).

## 5. 데이터 모델 (localStorage `billbox:v1`)

```
item = { id, name, kindId, amount|null, due 'YYYY-MM-DD', day(기준일),
         repeat: monthly|bimonthly|quarterly|half|yearly|none, months:[6,12]|null,
         estimated(고지서 없이 예상한 마감), tag:'독촉'|'압류예고'|'', note, source: photo|manual,
         paidAt(한 번만 항목이 낸 경우), history:[{due, amount, paidAt}], createdAt, updatedAt }
settings = { remindHour:9, remindDays:[3,0], push:'on'|'off', deviceKey, introSeen }
```
- 반복: [냈어요] → 기록에 넣고 `nextDue`로 넘김(`estimated=true`, "예상" 배지). 기준일 `day`를 기억해 1/31→2/28→3/31로 밀리지 않음. 고정 달(자동차세 6·12, 재산세 7·9)은 다음 차례 달.
- 종류별 기본 반복: 전기·가스·수도·건보·연금·관리비·통신·구독·자동이체·대출 = 매월 / 자동차세·재산세 = 6개월(고정 달) / 과태료·기타 = 한 번.

## 6. 글자 읽기·추출 (js/ocr.js, js/extract.js)

- Tesseract.js 5.1.1 (jsDelivr) + 언어 kor+eng (`tessdata.projectnaptha.com/4.0.0_best_int`). 처음 한 번 내려받고 IndexedDB에 저장. 첫 화면에서 조용히 미리 받음(warmup).
- 두 번 읽기: ① 원본(긴 변 1700px, psm 3) ② 손질본(흑백·1% 자동대비·1.4배 대비·선명, 긴 변 2600px, psm 4).
- 규칙: 금액 = 천 단위 쉼표 숫자(1,000~5,000만). "원" 옆 +2, 납부할금액/청구금액/체납금액 줄 +3, 계좌번호 줄 −3, 미납(전월)/부가세/기본요금/연체금 줄 −3. 날짜 = 2026.09.10 / 2026년 9월 10일 / 2026.1 0.1 0. 모두 인정, 월·일 범위 검사, 기한/까지/마감 줄 +3, 기준일/작성/체납기간 줄 −3. 두 결과의 후보를 합쳐 투표. 종류 = 가장 많이 나온 이름.
- 확신 표시: 1등 점수 ≥4이고 2등의 1.5배 이상일 때만 "확인!" 없이 통과. 아니면 빨간 확인!.
- 아무것도 못 읽으면 직접 입력 화면으로 넘기고 안내.

## 7. 알림

- **푸시(Web Push, VAPID)**: 설정에서 켜기 → 브라우저 권한 → 구독을 `/api/billbox/sync`에 저장. 항목이 바뀔 때마다 이름·마감일 목록을 다시 올림(1초 모아서). Vercel Cron이 **매시 정각** `/api/billbox/send` 호출 → 한국 시간 "지금 시"가 기기의 알림 시각과 같은 기기만 처리 → 설정한 N일 전·당일·(넘기면)다음날 1회. 같은 항목·같은 날 중복 없음. 죽은 구독은 삭제.
- **캘린더(.ics)**: 상세 화면에서 파일 받기. Getset 방식. VALARM 3일 전·당일(설정 따름). 푸시 못 쓰는 폰·아이폰 대비.
- 아이폰: 홈 화면 추가 후에만 푸시 가능(iOS 16.4+). 설정 화면에 안내. **미확인.**

## 8. 서버 (api/billbox/)

| 파일 | 역할 |
|---|---|
| `_lib.js` | Upstash REST 호출, web-push 발송, 한국 시간 |
| `config.js` | GET → VAPID 공개키 |
| `sync.js` | POST 저장 / POST test 시험 알림 / DELETE 삭제 |
| `send.js` | Cron(매시). `?force=1&hour=9`로 수동 시험(CRON_SECRET 필요) |
- 저장 구조: `bb:dev:{기기키}` = { sub, hour, days, items:[{id,name,due}], sent:{…}, updatedAt }, `bb:devices` = 기기키 집합.
- 환경변수: `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `CRON_SECRET`. (설정 순서는 §11)
- 비용: Upstash 무료 등급(일 1만 명령)이면 기기 수백 대까지 0원. 넘기면 Vercel/Upstash 비용 발생 → 그 시점을 대표에게 알릴 것.

## 11. 배포·설정 순서 (대표가 할 일)

1. zip의 `billbox/`, `api/`, `docs/`, `vercel.json`, `package.json`, `.gitignore`, `sitemap.xml`을 저장소 루트에 업로드(https://github.com/iason153/pebble/upload/main). Vercel이 자동 배포.
2. Vercel 대시보드 → 프로젝트 → **Storage** → Upstash Redis(무료) 만들어 연결 → `UPSTASH_REDIS_REST_URL/TOKEN` 자동 등록 확인.
3. **Settings → Environment Variables**에 추가: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`(별도 전달한 vapid.txt), `VAPID_SUBJECT`=`mailto:creatorock153@gmail.com`, `CRON_SECRET`(아무 긴 문자열). 저장 후 **Redeploy**.
4. 폰 크롬에서 /billbox/ → 설정 → 알림 켜기 → 시험 알림이 오면 성공.
5. Cron 확인: Vercel → Cron Jobs 탭에 `/api/billbox/send` 매시 실행 표시.

## 13. v1.0.1 변경 (실제 폰 첫 사용 피드백 반영)

- 피드백: 카톡 캡처 읽는 데 너무 오래 걸림. 읽는 중 화면 꺼지면 멈추는지?
- 원인: ① 첫 실행은 한글 사전(약 10MB)+엔진 내려받기 ② 매번 두 번 읽기 ③ 안드로이드 크롬은 화면이 꺼지면 작업 정지.
- 조치:
  1. **Wake Lock** — 읽는 동안 화면 안 꺼짐(`navigator.wakeLock`, 크롬 안드로이드 지원. 미지원 브라우저는 조용히 무시).
  2. **적응형 2단계** — 1차(원본)만으로 금액·기한 둘 다 "확신"이면 2차 생략 → 시간 절반. 자신 없을 때만 손질본을 한 번 더.
  3. 사진 크기 축소 1700→1400 / 2600→2000.
  4. 규칙 보강: 표 모양(이름표 윗줄, 값 아랫줄)도 윗줄 이름표에 가점. 확신 기준 4→3.
  5. 진행 화면에 경과 초·"화면을 켜 두세요"·"처음엔 사전 내려받아 1분쯤" 안내.
  6. **📤 공유 버튼**(상단, Getset share.js 재사용, utm_source=share).
- GA4 `scan_done`에 `passes`(1|2) 추가 → 2차까지 간 비율을 보고 기준을 조정한다.
- 서비스워커 캐시 v2.

## 14. v1.0.2 — 치명 버그 수정 (첫 사진 읽기 전부 실패, 8분 넘게 멈춤)

- 원인: `config.js`의 `LANG_PATH`를 `https://tessdata.projectnaptha.com/4.0.0_best_int`로 두었는데 **그 주소에는 best_int 폴더가 없다(404)**. Tesseract.js는 404를 받아도 오류를 내지 않고 영원히 기다린다 → 사용자 화면이 "내려받는 중"에서 멈춤. 샌드박스 테스트는 CDN을 로컬 파일로 돌려서 통과했기 때문에 못 잡았다. (교훈: **CDN 주소는 배포 전에 실제 HEAD 요청으로 확인할 것** — ways-of-working에 추가)
- 수정:
  1. `LANG_PATH` 비움 → Tesseract.js 기본값(jsDelivr `@tesseract.js-data/{언어}/4.0.0_best_int`, 존재 확인함. kor 1.6MB + eng 2.9MB + 엔진 3MB ≈ 7.5MB).
  2. 언어 파일 주소를 **HEAD로 먼저 확인** → 404면 즉시 실패 표시.
  3. 준비 전체에 **150초 타임아웃** → 넘기면 "너무 오래 걸려요, 와이파이에서 다시" + [다시 받기].
  4. **홈 상단 "읽기 준비" 배너**(대표 제안): 첫 방문에 진행률·용량·"다른 건 다 써도 돼요" 안내 → 끝나면 "찍을 준비 됐어요" 6초 후 사라짐. 이미 받아 둔 폰에선 안 보임. 실패하면 빨간 배너 + [다시 받기].
  5. 찍기 버튼을 준비 전에 누르면 토스트로 상태 안내(막지는 않음).
- 테스트: 404 흉내 → 즉시 오류 배너 → 정상 주소로 [다시 받기] → 준비 완료 → 읽기 성공(합성 가스 고지서 3.5초).

## 15. v1.0.3 — "메모리가 부족하여 이 작업을 마무리할 수 없습니다" 대응

- 증상(갤럭시 S21, 크롬): 사진을 올리면 위 문구가 뜨고 사진이 사라짐. 다른 탭 여러 개 열려 있었음.
- 원인(추정): 안드로이드는 카메라 앱으로 넘어간 사이 메모리가 모자라면 크롬 탭을 꺼 버린다. 빌박스가 읽기 엔진(한글 사전 포함)을 미리 메모리에 올려 둔 상태 + 다른 탭 + 카메라 앱이 겹침. 1,200만 화소 사진을 원본 크기로 푸는 것도 부담.
- 조치:
  1. **미리 받기는 받기만**: 사전·엔진을 내려받아 브라우저 저장소(IndexedDB)에 넣은 뒤 **메모리에서 내림**. 받아 둔 표시(`billbox:ocr-cached`)가 있으면 다음 방문엔 아예 안 올림.
  2. **찍을 때만 올리고, 다 읽으면 바로 내림**(`release()`). 다음 찍기 땐 저장소에서 몇 초 만에 다시 올라옴.
  3. **앱 안 카메라**(getUserMedia): "📷 카메라로 찍기"가 카메라 앱으로 넘어가지 않고 시트 안에서 찍음 → 크롬이 꺼질 일 없음. 안내 테두리("금액·납부기한이 이 안에 크게"), 불빛(지원 기기만). 권한 거부·미지원이면 "카메라 앱으로 찍기"(기존 방식)를 보여 줌.
  4. **사진을 열 때부터 작게**: `createImageBitmap(resize…)`로 긴 변 1400px로 바로 디코딩(원본 전체를 메모리에 안 풂). 엔진은 사진을 줄인 **뒤에** 올림.
  5. **사진 사라짐 안내**: 앨범·카메라 앱으로 가기 전 표시를 남기고, 크롬이 꺼졌다 다시 열리면 찍기 시트를 열어 "사진이 사라졌어요 → 앱 안 카메라/앨범, 다른 탭 닫기" 안내.
  6. 앨범·카메라 앱으로 넘어가기 직전에도 엔진을 내림.
- 테스트: 미리 받기 후 메모리 해제 확인, 앨범 읽기(152,870 / 2026-12-05, 3.5초), 가짜 카메라로 앱 안 찍기 → 읽기 화면 → 카메라 꺼짐, 사라짐 안내 표시, 화면 크기 회귀 통과.
- 남은 확인: 실제 S21에서 다른 탭 열어 둔 채 앱 안 카메라로 찍기. 아이폰 미확인.

## 18. v1.1.2 — 읽기 도구가 "될 때도 있고 안 될 때도 있는" 문제 (2026-10-15)

- 증상: 어떤 때는 "읽기 도구가 준비 안 됐어요"로 못 읽고, 어떤 때는 잘 읽음.
- 원인(코드 점검으로 확인):
  1. **엔진을 외부 CDN(jsDelivr)에서 매번 받음** — v1.0.3부터 메모리 절약을 위해 읽고 나면 엔진을 내렸는데, 다시 올릴 때마다 CDN에서 엔진 파일을 받아야 했다. 폰 인터넷이 잠깐 느리면 실패.
  2. **경쟁 버그** — 첫 화면의 미리 받기(warmup)가 끝나면 엔진을 내리게 해 뒀는데, 그 순간 사용자가 찍고 있으면 **읽는 도중 엔진이 꺼졌다**.
  3. **준비 확인(HEAD) 요청이 일시 오류(403·429 등)에도 실패 처리** — 404일 때만 실패여야 했다.
- 조치:
  1. **엔진·한글 사전을 우리 사이트에 둠**: `billbox/vendor/`(약 12MB: tesseract.js 5.1.1, core lstm 2종, kor·eng best_int). CDN 의존 없음(글꼴만 CDN).
  2. **서비스워커가 엔진 파일을 폰에 저장**(`billbox-engine-r2` 캐시, 앱 업데이트해도 유지) + Vercel 헤더로 1년 캐시. 한 번 받으면 **인터넷이 끊겨도 읽힘**(시험 통과).
  3. **사용 중 표시(lease)**: 읽는 중이면 엔진을 절대 안 내림. 다 읽고 45초 안 쓰면 내림(연달아 찍기는 바로).
  4. 준비·읽기 실패 시 **자동으로 한 번 더**(망가진 엔진은 버리고 새로). 준비 확인 요청 삭제.
  5. 이미 받아 둔 폰에선 엔진을 다시 올릴 때 홈 배너를 안 띄움.
- 시험: 외부 CDN 완전 차단 상태에서 ① 미리 받기 도중 바로 찍기 ② 연달아 찍기(2.9초) ③ 엔진 내린 뒤 **오프라인**에서 찍기(3.5초) 모두 정상.
- 배포: `vercel.json`에 headers 추가됨 → 루트 vercel.json도 올릴 것. vendor 폴더째 업로드.

## 20. v1.1.4 — 앱 안 카메라로 찍으면 거의 못 읽음 (2026-10-15, 대표 시험)

- 원인: 앱 안 카메라가 **미리보기 영상의 한 장면**을 잘라 썼다. 영상은 사진보다 해상도가 낮고(보통 720~1080줄) 압축·흔들림·초점 문제로 글자가 뭉개진다.
- 조치:
  1. **ImageCapture.takePhoto()**로 카메라 원래 화질 사진을 찍음(초점·노출 자동, 지원 기기에선 플래시). 안 되면 미리보기에서 **테두리 안쪽만 잘라** 글자를 크게.
  2. 미리보기 해상도를 최대(4K 요청)로, 계속 초점(continuous focus) 켜기.
  3. **"📸 카메라 앱으로 찍기 · 화질 최고"를 항상 함께 보여 줌**(앱 안 카메라가 안 맞는 폰 대비). 엔진은 이미 메모리에서 내려 둬서 크롬이 꺼질 위험이 낮아짐(v1.0.3·v1.1.2).
  4. **금액·기한을 하나도 못 읽으면** 바로 직접 입력으로 보내지 않고, 찍기 화면으로 돌아와 "더 가까이·밝은 곳에서 다시" 안내 + [그냥 직접 입력].
  5. 글자 읽기 해상도를 올림(1차 1400→1700px, 2차 손질본 2000→2400px).
  6. 해상도를 올리자 생긴 날짜 회귀 수정: 점이 하나 빠진 "2026. 12 05"도 날짜로 인정, "~·부터·사이"가 있는 기간 날짜 감점, 오늘에서 너무 먼 날짜(석 달 전보다 이전·넉 달 뒤보다 이후) 감점, 점수 낮은 날짜는 "혹시 이건가요?" 후보로도 안 보임.
- GA4: `cam_open`(미리보기 해상도·ImageCapture 지원 여부), `cam_shot`(photo|frame) → 실제 폰에서 어떤 방식으로 찍히는지 확인할 것.
- 미확인: 실제 S21에서 takePhoto 화질·속도. 그래서 대표 시험 결과가 필요.

## 21. v1.2.0 — 읽기 정확도 끌어올리기 (2026-10-15, 대표 요청: "비용 드는 것만 보류하고 최대한 개선, 제일 못 읽는 건 수도요금")

목표는 **간편함**. 고지서를 펴서 한 장 찍으면 끝나야 함. 막히던 곳이 읽기 단계라서, 돈 안 드는 방법을 모두 넣음. 서버·유료 AI 읽기(6번)는 보류.

### 21.1 자동 읽기 개선 (사진 → 무엇을·얼마·언제까지·계좌)
| 항목 | 내용 |
|---|---|
| 해상도 | 원본을 통째로 열어 긴 변 2600px로(이전 1600). 줄일 때 **부드럽게 하기 'low'**(시험해 보니 'high'가 글자를 뭉개 오히려 나빠짐) |
| 1차 읽기 | 쪽 전체(psm 3), 단어 위치까지 받음 |
| **이름표 찾아 다시 읽기** | 1차에서 "청구금액·납기내·납부기한…" 이름표 위치를 찾아(글자 사이 띄어쓰기 무시), 그 오른쪽/아래 숫자만 잘라 크게 키워 숫자 전용으로 다시 읽음 |
| 2차 읽기 | 대비 높인 판 2000px, psm 4 |
| 금액 규칙 | 이름표 **바로 앞**이면 크게 가산, 같은 줄이면 조금. 쉼표 없는 숫자도 "원"이 붙거나 금액 이름표 뒤면 인정. 납기후·감면·정액요금·물이용부담금 감점 |
| 날짜 규칙 | 시각(오전/오후, 12:30)·기간(~)·사용기간·검침일·단가 감점. 2623→2023 같은 연도 오독 고침. **납기내/납기후 짝**(14~75일 차이)이면 앞의 것. 점수가 마이너스면 빈칸(틀린 값보다 빈칸이 나음) |
| 연도 없는 날짜 | "납부기한 10/30", "납기 3월 31일" — 바로 앞에 기한 이름표가 있을 때만, 연도는 오늘에 가까운 쪽 |
| 계좌 | 은행 이름이 없는 "116100-64-872060" 모양도 잡고, 잘린 "농협 116100-64-8"과 합침. 전화번호 모양은 제외 |
| 종류 | 전기 인식어 추가(한국전력·주택용전력·전력량·kWh), 월세·보험·학원 종류 추가 |

### 21.2 시험 결과 (대표가 보낸 고지서 5장, 채팅으로 줄어든 사진)
| | 처음 | v1.2.0 |
|---|---|---|
| 종류 | 4/5 | **5/5** |
| 금액 | 3/5 | **4/5** |
| 기한 | 1/4 | **4/4** |
| 계좌 | 1/2 | **2/2** |

- 한 장당 4~12초(시험 컴퓨터). 폰은 더 걸릴 수 있음.
- **수도요금 금액은 여전히 자동으로 못 읽음**: 분홍 칸 안의 작은 글씨 + 채팅으로 줄어든 사진(907px). 원본(폰 사진 약 4000px)이면 나아질 여지 있음 → **대표 S21 원본으로 확인 필요**. 그래서 21.3을 만듦.

### 21.3 📍 사진에서 콕 찍기 (새 기능)
- 확인 화면의 금액·날짜·계좌 칸 아래 버튼 → 사진이 크게 열림 → **그 숫자를 손가락으로 톡** → 누른 곳 주변만 잘라 키워 숫자 전용으로 3~4번 읽고 투표 → 칸에 채움(✓는 사용자가 누름).
- 확대·이동·회전 상태에서도 정확한 지점 계산. 콕 찍기 화면에선 두 번 톡 확대를 끔(톡=고르기).
- 원본 큰 사진에서 읽음(저장용 1700px 사진이 아니라). 저장된 항목 고치기에선 저장된 사진으로.
- 자신 없이 읽은 값이 자동 읽기 후보와 한 글자만 다르면(03↔05) 후보 쪽을 택함.
- 자동으로 금액·기한을 하나도 못 읽은 경우에도 "📍 사진에서 직접 콕 찍기" 버튼으로 바로 이어감(다시 안 찍어도 됨).
- 시험: 고지서 4장 10곳 중 **9곳** 맞음(수도 금액·기한·계좌 모두 맞음). 한 번에 1~3초.
- 사진 보관을 "끔"으로 해도 확인 화면에선 콕 찍기 가능.

### 21.4 📋 카톡·문자 고지서 글
- 찍기 화면에 "카톡·문자 글 붙여넣기" → 글 칸 + [붙여넣기][이 글 읽기]. 사진과 같은 규칙으로 읽음. 글이라 오독이 없음.
- 카톡·문자에서 **공유 → Billbox**로 글을 보내도 됨(manifest share_target의 title·text·url, 서비스워커가 폰 저장소에 잠깐 두고 앱이 읽음).
- 시험 문구 4종(수도·전기·가스·건보) 모두 금액·기한 맞음.

### 21.5 해 본 것 중 안 넣은 것
- 'high' 부드럽게 줄이기: 정확도 하락.
- Sauvola 흑백 처리: 비슷한 정확도에 2배 느림 → 끔(코드엔 남김).
- 큰 전체 사진을 그대로 읽기: 느리고 날짜 오독 늘어남.

## 22. v1.2.1 — 찍기는 폰 카메라 앱 하나로 (2026-10-15, 대표 피드백: "앱 안에서 찍으면 아직도 인식이 안 됨")

- 못 읽었을 때 안내도 "카메라 앱으로 찍기" 대신 "📍 콕 찍기"로 바꿈.
