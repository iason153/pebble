- 작성 2026-10-14, v1.1 같은 날(폰 테스트 피드백 8건 반영), v1.2 장부 용량 대책, v1.3 위치 좌표 표시·스토리 규격, v1.4 얼굴 자동 찾기, v1.5 얼굴 가리기 방식(스티커) · Pebble 네 번째 툴 · 주소 https://pebbleitgo.com/seal/ · 폴더 `seal/`
- 한 줄: SNS에 올리기 전 한 번 거치면, 위험한 것을 가리고 보이지 않는 도장을 심어 주는 도구. 사칭 계정을 발견하면 캡처 한 장으로 내 사진임을 확인하고 신고 카드를 만든다. 사진은 기기 밖으로 나가지 않는다.
- 사전 시험 결과: `docs/Seal_사전시험_결과_v0.md` (바둑판 도장이 재압축·잘림·캡처를 견디는지 검증한 기록)

## 1. 목적과 차별성
- 가장 주요한 목적: **사칭 계정을 발견했을 때, 그 사진이 내 것임을 1분 안에 보여 주는 신고 자료를 만든다.**
- 올리기 전 점검(위치 정보·번호판·문패 가리기)은 그 앞에 붙는 예방 단계.
- 차별성: 점검 + 숨은 도장 + 캡처 한 장으로 신고 카드까지 한 흐름 / 한국어 / 설치·가입 없이 웹 / 사진·열쇠가 폰 밖으로 안 나감 / 어디까지 견디는지 수치로 공개.
- 약속하지 않는 것(이름·문구에 쓰지 않음): 도용 자체를 막는다, 모든 글자를 찾는다, 법적 증거가 된다.

## 2. 비용·개인정보 원칙
- 서버 없음, 유료 AI 없음, 로그인 없음. 모든 계산은 브라우저(워커) 안.
- 글자 자동 찾기(Tesseract.js)는 CDN 대신 `seal/vendor/tesseract/`에 자체 호스팅(약 10MB, 누를 때만 내려받음).
- GA4(G-4Q8F4E2J61, tool=seal): 단계 완료 여부·점수 구간·걸린 시간 등 사용 패턴만. 사진·이름표 글자·백업 코드는 절대 보내지 않음.
- 저장: 열쇠 `localStorage seal:key`, 이름표 즐겨찾기 `seal:tags`, 도장 장부 `IndexedDB seal/ledger`(사진 전체 blob·축소본·날짜·회색 지문·이름표, 최근 50장), 공유 받기 임시 파일 `Cache seal-share`.

## 3. 디자인
- Pebble 안에서 **툴마다 자기 개성**을 가진다(2026-10-14 대표 결정). Seal은 사진을 올리는 여성 사용자를 생각해 **밝고 가벼운 크림 바탕 + 로즈 + 샴페인 골드**.
- 색: 바탕 크림 #FDF8F3(옅은 복숭아·라벤더 빛), 글자 #2B2628, 주 버튼 로즈 #C96B7E→#B04A62, 강조 골드 #C9A86A(도장·확인됨에만), 틴트 살구 #FBE9E8 / 복숭아 #FDEFE3 / 라벤더 #F0E9F7.
- 제목 나눔명조(Google Fonts), 본문 시스템 고딕. 알약 버튼, 둥근 모서리 20px, 로즈빛 옅은 그림자, 가는 선.
- 홈 구성(2026 트렌드 참고: 벤토 그리드·전후 비교·정돈된 여백): 명조 제목 → 큰 버튼 2개 → **벤토**(큰 칸: 도장 찍은 사진 ↔ 드러낸 모습 **비교 슬라이더**, 작은 칸: 0건·217/220·1분·가리기 등 장점 숫자) → 이렇게 써요 → 한계.
- 아이콘: 복숭아·라벤더 바탕에 로즈 도장.

### 사진 지키기 (단계 표시: 점검 → 도장 → 내보내기)
1. **점검**: 사진을 고르면 EXIF에 위치 정보(GPS IFD)·촬영 정보가 있는지 칩으로 표시. 안드로이드 10+는 앱(크롬 포함)이 갤러리에서 사진을 가져갈 때 위치 정보를 자동으로 지워 넘기므로 갤러리로 고른 사진은 대부분 "없음"으로 나온다(칩 문구: "폰이 미리 지웠을 수 있어요"). "내 파일"로 고르면 남아 있을 수 있음. 인스타 앱은 위치 권한을 따로 받아 원본 위치를 읽을 수 있으므로 Seal을 거치는 의미는 유지. v1.3부터 **위도·경도를 읽어 "북위 37.3614, 동경 126.9352"처럼 보여 주고**(주소 변환은 외부 API라 안 함) "집·회사·아이 학교 근처면 특히 조심" 힌트. 내보낼 때 캔버스 재인코딩으로 자동 삭제.
   - 손으로 가리기: 브러시(가늘게/보통/굵게)로 문지르면 모자이크(블록 = 긴 변/60). 되돌리기 12단계(획의 영역만 저장).
   - **얼굴 찾아보기**(v1.4): picojs(MIT, 순수 JS, 모델 240KB, `vendor/pico/`)를 누를 때만 불러와 1000px 축소본에서 0°·±20°·±40° 회전으로 검출, 점수 10↑, 겹침 제거. 정면 위주(옆얼굴·가려진 얼굴 놓침, 문구로 명시). 결과는 둥근 네모("얼굴 가리기") → 탭하면 가림. v1.5: 가리기 방식 선택 **모자이크 / 흐림 / 스티커(😊 😎 🙂 🐻 🌸 ⭐ ❤️, 폰 글꼴의 이모지라 추가 파일·저작권 문제 없음)**. 스티커는 얼굴보다 15% 크게, 되돌리기 영역도 그만큼 넉넉히 저장. 브라우저 내장 FaceDetector는 안드로이드 크롬에서 플래그 뒤라 사용 안 함, MediaPipe는 20MB라 제외.
   - 글자 찾아보기: Tesseract(eng, psm 11)로 1600px 축소본에서 단어 상자 추출 → 숫자 2개 이상(신뢰도 35↑) 또는 영문 4자 이상(70↑)만 표시. 상자 탭 → 모자이크(블록 = 상자 높이/2.5 이상), "모두 가리기". 한글·작은 글자는 놓칠 수 있다고 문구로 명시.
   - 체크리스트(문패·번호판·송장·반사·아이 이름표)
2. **도장**: 보이지 않는 도장(기본 켬) / 보이는 이름표(기본 끔, 켜면 글자 입력 + 구석에 작게·가운데 옅게) / **스토리 규격으로**(1080×1920, 빈 곳은 사진을 늘려 흐린 배경, 기본 끔) / 크기 줄이기(2048px, 기본 끔)
3. **저장·공유**(버튼 "도장 찍기" → "저장하거나 공유하세요"): 한 일 목록, **저장**(a[download]) / **공유하기**(navigator.share files → 안 되면 저장). "아직 저장되지 않았다"를 명시. 도장 장부에 **도장 찍은 사진 전체(JPEG)** + 320px 축소본 + 날짜 + 이름표 정보 보관. **기록은 500장까지, 완전한 사진은 용량 한도(기본 150MB, 설정에서 50/150/400MB)까지** — 한도를 넘으면 오래된 사진의 원본 크기만 지우고 **1280px 중간본(`mid`, 150~250KB)**·날짜·축소본은 항상 남김(`photoDropped`) → 카드는 중간본으로 완성. 갤러리에서 다시 고르는 건 예비 경로(안드로이드 크롬은 자기 다운로드 파일을 갤러리로 고르면 읽기 거부되는 문제가 있어 "내 파일"로 고르도록 안내). 저장 실패 시 축소본만 남기고 안내.
   - 글자 찾기 결과는 사진 **아래 결과 띠**(찾은 수 / 못 찾음 + 정확도 문구, 사진을 가리지 않도록 v1.4에서 아래로 이동). 도장 토글 아래 열쇠 앞 4자리 포함 안내 한 줄. 이름표는 최근 5개를 칩으로(localStorage seal:tags).

### 내 사진인지 확인
- 캡처·사진 고르기 → 1400px로 줄여 워커에서 찾기(진행 막대) → 7.5 미만이면 좌우 반전으로 한 번 더.
- 결과: 확실(9↑) / 약함(7.5~9) / 못 찾음. 점수·걸린 시간·도장 한 칸 크기. 장부 대조(템플릿 매칭, 닮은 정도 0.62↑ 이고 2위와 차이 0.04↑)로 자동 추정, 틀리면 **"장부에서 직접 고르기"** 시트. 장부에 큰 사진이 없으면 **"갤러리에서 내 사진 고르기"** → 그 파일에서 같은 열쇠 도장을 찾아(7.5↑) 확인한 뒤 카드에 쓰고 장부 기록에 다시 채움.
- **신고 카드**(1080×1920 JPEG): ① 의심 계정 캡처 ② 내 사진(장부의 완전한 사진, 이름표가 있으면 빨간 테두리로 위치 표시) ③ 캡처 속 도장을 **로즈색으로 진하게 드러낸 모습** + 가운데 2×2칸 확대 + 이 열쇠의 도장 무늬(기준) · 점수·판정 · 열쇠 앞 4자리 · 확인 시각 · "법적 증거 아님, 도장은 사진 자체에는 안 보임" 문구. 저장/공유.
- 설치된 Seal(갤럭시)로 갤러리에서 공유 → `share_target`(POST `/seal/share-target`) → 서비스워커가 파일을 Cache에 두고 `./?shared=1`로 보냄 → 바로 찾기 시작.

### 설정 시트
- 백업 코드(8자리 16진수) 보기·복사, 코드로 열쇠 바꾸기, 장부 사용량(기록 수·완전한 사진 수·MB/한도), 보관 한도 50/150/400MB(`localStorage seal:ledgerMB`), 큰 사진만 비우기(기록 유지), 전부 비우기.

## 5. 도장 알고리즘 (js/seal-core.js, 사전 시험으로 확정)
- 열쇠(32비트) → mulberry32로 64×64 가우시안 잡음 → FFT 대역 6~22 주기만 남김 → 한 칸 무늬. 사진 긴 변 ÷ 6 크기로 바둑판 반복.
- 세기: 밝기(Y) 0.6, 파랑-노랑 색차(Cb) 2.0. 질감 마스크(평평한 곳 0.15배 / 무늬 많은 곳 최대 3배, 어두운 곳 약하게), 색차 마스크는 0.5~1.5배.
- 찾기: Y·Cb를 각각 고역 통과·국소 정규화 → 배율 0.2% 간격(한 칸 64~700px)으로 줄이며 64×64로 접기 → 주파수별 백색화 → 열쇠 무늬와 순환 상관 → 두 층의 정규화 상관을 합산 → 최고 봉우리 = 점수.
- 판정: 9↑ 확실, 7.5~9 약함. 도장 없는 사진 270장 × 열쇠 21개 = 5,670회에서 7.5 초과 0건(최고 7.25).
- 검증(사진 10장 × 27상황): 주요 22상황 217/220. 약한 상황: 480px 축소 6/10, 5% 늘림 7/10, 1° 기울임 6/10, 격자 썸네일 3/10, 3° 기울임 0/10.
- 속도(서버 CPU 기준): 심기 0.4~1초(6MP), 찾기 6~13초(1400px). 폰은 미확인.
